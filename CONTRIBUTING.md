# Contributing

Read `AGENTS.md`, `docs/CORRECTIONS.md`, and the relevant function contract. Propose a bounded change with intended behavior, source/correction IDs, affected files, and acceptance cases.

Use synthetic fixtures. Preserve existing user choices and separate new proposals from confirmed requirements. Update affected documentation and record actual verification, including failures and skips.

Portable code should use configuration rather than personal paths or hardcoded profile blurbs. Separate host adapters from workflow logic; keep permissions outside model-only instructions.
