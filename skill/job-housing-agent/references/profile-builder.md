# Indeed and ZipRecruiter profile builder — explicit function

This function drafts platform profile copy from the user's confirmed profile and corrections. It is separate from tailoring a resume for a specific application.

## Build

For a new user, ask plain questions one group at a time: jobs/titles/dates/duties; education and credential status; desired work and pay preferences; commute and car access; housing needs and deadline. Build a private draft profile/policy from the answers and read it back for confirmation. Do not require manual JSON editing or infer unsupported facts. If private file access is unavailable, return a draft to save and disclose that it has not been persisted.

From verified facts and the user's chosen career direction, draft platform-appropriate headline, summary, skill tags, employment entries with separate titles/dates, education, credential status, availability, location/commute preferences, and screening defaults. Relevant coursework should match the actual domain; a course is not a professional certification.

Use truthful transferable evidence to lead toward the chosen field without rewriting actual job titles or claiming experience not held. Keep personal identifiers private and only use them in fields the user authorizes. Do not publish a mailing address as though it were current residence.

## Verify and reconcile

- Read the canonical source and latest corrections before drafting.
- Compare current saved profile text and attached/default resume against the proposed version when live access is authorized.
- Check employment title/date boundaries, graduation year, credential status, availability, languages, and required screening answers.
- Check the default resume on each platform separately. A role-specific upload can alter an account default; do not presume the next application uses the correct file.
- Verify saved text and resume filename/preview after an authorized update. Distinguish draft, attempted edit, confirmed saved state, and unsupported field.
- Do not assume a profile update repaired existing application records, earlier uploads, or generated documents.

## Output and authority

Return separate Indeed and ZipRecruiter copy packs, source-to-field mapping, discrepancies, resume-selection advice, and a private update checklist. Platform field limits/interfaces must be checked in the actual current host; historical UI recipes are not universal instructions.

Default action is drafting. Live profile edits and resume uploads require scoped user authority. Submitting applications, changing visibility/contact preferences, messaging recruiters, or sharing additional personal information is separate. A blocked native file picker or unsupported connector is reported, not bypassed.

A searchable profile can make experience visible to recruiters; this package does not claim that particular wording guarantees discovery, interviews, or offers.
