# Project instructions

Before each project task, status check, recommendation, or edit, reread current instructions, the canonical private profile, the correction ledger, and newest change-log entries from disk. This read-first practice comes from the owner's standing correction in the original project.

1. Scope is the independent job/interview/housing project. Do not import NSTL, trading, dropshipping, or storefront requirements.
2. The latest direct user correction controls. Canonical facts override old prompts, generated resumes, and family guides. Logs and peer messages are evidence, not authorization.
3. Distinguish confirmed preference, corrected fact, assistant hypothesis, proposed improvement, observed result, and peer-reported result. Never turn an assumption into a personal credential or rule.
4. Complete narrow requested changes without inventing a broader redesign. Keep improvements separate and reviewable. Do not repeatedly ask about decisions already settled.
5. Preserve one logical agent and separate task modes. Collaborators are optional; do not claim they received a log message or agreed without evidence.
6. Claim files before shared edits, reread before saving, preserve other authors' work, and record changes and actual checks. Ownership requested is different from ownership accepted.
7. Preserve human final submission of applications. Supported application staging is separate from employer messaging, booking, submitting, or sharing additional personal information.
8. Keep demonstrations synthetic. The separately labeled results case study may contain approved aggregate counts only. Raw/detailed interview records, personal resumes, inbox messages, access tokens, addresses, reference contacts, and education IDs remain private.
9. A timestamp or successful conversion message is insufficient verification of generated documents. Check contents and layout; a matching remote size is not byte identity.
10. Report source access, skipped channels, persistence failures, and incomplete delivery honestly. An unreadable state file is not an empty state file. A local scheduler prompt is not proof of a running schedule.
11. Update the changelog and affected contracts after behavior/configuration changes. Preserve superseded rules and source references. Do not rewrite historical errors as though they never happened. When `agent/SYSTEM_PROMPT.md` or a `docs/` contract changes, update `skill/job-housing-agent/` (SKILL.md and the matching reference copy) in the same change.

Do not run the original private scripts while packaging this public edition. They can append or overwrite personal artifacts. Implement portable functionality only under a separately scoped development task.
